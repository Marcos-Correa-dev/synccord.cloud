## OBSERVAÇÕES TÉCNICAS

### Main Process (Node.js)
- O processo principal (`index.js`) é responsável por:
  - Criar a janela do Electron (`BrowserWindow`)
  - Configurar auto-updater
  - Gerenciar o ciclo de vida do app
  - Configurar IPC entre processos
  - Injetar o User-Agent customizado

### Renderer Process (Chromium)
- O conteúdo visual (React/CSS) NÃO está no asar principal
- O app carrega o frontend via URL: `https://discord.com/app`
- O app.asar é apenas o "wrapper" Electron — a UI é uma WebApp normal

### Módulos Nativos (.node)
- `discord_voice`: Módulo C++ para captura de áudio/voz
- `discord_utils`: Acesso a APIs nativas do SO
- `discord_spellcheck`: Integração com spell check do SO
- Esses módulos são compilados para cada plataforma

### IPC Channels observados (via análise de código)
- `DISCORD_RELAUNCH`         — reiniciar o app
- `DISCORD_SCREENSHOT`       — captura de tela
- `WINDOW_MINIMIZE/MAXIMIZE` — controle da janela
- `PUSH_TO_TALK_*`          — teclas de push-to-talk
- `OVERLAY_*`               — overlay de jogo
- `RPC_*`                   — Rich Presence local

## CONCLUSÃO PARA O CLONE

O app Discord Desktop é fundamentalmente um **browser Electron** carregando
uma WebApp hosteada nos servidores do Discord. Para o nosso clone:

1. O "app desktop" é Electron wrapping nossa WebApp (NestJS serve as views)
2. Os módulos nativos de voz precisam ser reimplementados (via mediasoup-client)
3. O IPC pode ser simplificado (window controls básicos)
4. Rich Presence pode ser adicionado na fase 4+
